# 頁面：輪播、固定與依情境顯示

一塊螢幕可以有多個頁面：儀表板、貓咪房間、遊戲頁面。本指南說明每一刻螢幕上顯示的是哪一頁。

## 頁面如何輪播

- **輪播。** 已啟用的頁面輪流顯示，每頁依自己的「顯示時長」（`durationMs`，預設 10 分鐘），以時鐘時間為準：兩台頁面相同的 Kiosko 顯示同一頁。
- **顯示時段。** 頁面可以「一律」顯示、僅在「工作時間」顯示，或僅在「工作時間以外」顯示（`when`，依據設定裡的工作時間）。
- **固定。** 頁面卡片上的圖釘會讓該頁一直顯示（`pinnedPage`；Home Assistant 和 API 也可以固定頁面）。
- **插播動畫**每隔一段時間蓋在目前頁面上播放，**警報**則凌駕一切，佔據整塊螢幕。

## 在以下情況顯示此頁面…

頁面也可以在某件事發生時**自動出現**：遊戲開啟了、你在通話中、電價很貴、週五晚上、會議即將開始。開啟該頁面（點擊其卡片，再點擊畫布上的空白處），在其設定的**在以下情況顯示此頁面…**中新增條件：

| 條件 | 符合的時候… |
|---|---|
| **某個程式開啟時** | 有該名稱的程序正在執行。萬用字元，不分大小寫：`steam*`、`obs*`、`zoom*`；多個以逗號分隔。 |
| **資料來源的值** | 資料來源在某個路徑上的值符合比較，例如 `calls/active` · `active` · *為真*；`electricity/pvpc` · `now.price` · *大於* · `0.2`。 |
| **某個時段** | 本地時間落在該時段內，且在所選日期。`22:00` 到 `07:00` 跨越午夜。 |
| **本頁某個小工具緊急時** | 本頁某個小工具表示緊急（會議即將開始、有權限請求在等待）。 |

只要有一個條件符合，該頁面就會取代輪播佔據螢幕；都不符合後，輪播依時鐘時間恢復。帶條件的頁面**只在**條件符合時出現，除非你開啟「也參與一般輪播」。

- **同時多個。** 每個條件都有**優先順序**：最高者勝出。優先順序相同的頁面互相輪流。
- **不閃爍。** 情境頁面出現後至少停留 20 秒，條件不再符合後再停留 10 秒，以防它再次符合（遊戲重新啟動、數值在門檻附近徘徊）。這兩項依螢幕設定，在「防閃爍」中。優先順序更高的頁面無須等待。
- **先後順序**：警報，然後是固定的頁面，然後是情境頁面，最後是輪播。情境頁面顯示期間，排定的插播動畫會等待。
- **這頁為什麼在螢幕上？** 編輯器在頁面列表旁說明哪一頁佔據螢幕以及原因：*由此固定：遊戲已開啟 (steam)*。

條件可以有**名稱**（「遊戲已開啟」）：編輯器會把它當作原因顯示。在設定檔中，一個條件可以同時檢查多項，須全部符合：

```json
"showWhen": [
  { "label": "遊戲已開啟", "priority": 5, "app": "steam*, *.x86_64" },
  { "label": "通話中", "priority": 9, "source": "calls/active", "path": "active" },
  { "time": { "start": "18:00", "end": "23:00", "days": [5, 6] }, "source": "electricity/pvpc", "path": "now.price", "op": "lt", "value": 0.1 }
]
```

比較方式（`op`）：`truthy`（沒有 `value` 時的預設值）、`falsy`、`eq`（有 `value` 時的預設值）、`ne`、`gt`、`gte`、`lt`、`lte`、`contains`。尚未送出資料的資料來源，或不存在的路徑，永遠不符合。即使沒有小工具顯示該資料來源，它也會執行。螢幕的防閃爍設定為 `"context": { "minMs": 20000, "holdMs": 10000 }`。

### 各系統上的程式

僅在有條件需要時，Kiosko 每 3 秒查看一次正在執行的程式，只用任何使用者都能讀取的資訊：

- **Linux**：核心給每個程序的名稱（截斷為 15 個字元）以及啟動時使用的名稱（`argv[0]`，完整名稱）。如果 `/proc` 以 `hidepid` 掛載，只能看到自己的程序。透過 Steam Proton 執行的遊戲通常顯示為其 `.exe`（`*.exe` 可全部比對）。
- **macOS**：執行檔的名稱及其應用程式的名稱（`zoom.us`、`OBS`）。
- **Windows**：映像名稱，帶或不帶 `.exe`（`steam.exe`、`steam`）。

只讀取名稱，從不讀取命令列。容器裡或其他電腦上的程式看不到。

### 尚未支援

會議開始、Webhook、某塊螢幕開始串流，目前還不是獨立的條件；行事曆小工具的緊急狀態，或帶有該值的資料來源，可以涵蓋其中一部分。
