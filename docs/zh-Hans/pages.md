# 页面：轮播、固定与按情境显示

一块屏幕可以有多个页面：仪表盘、猫咪房间、游戏页面。本指南说明每一刻屏幕上显示的是哪一页。

## 页面如何轮播

- **轮播。** 已启用的页面轮流显示，每页按自己的“显示时长”（`durationMs`，默认 10 分钟），以挂钟时间为准：两台页面相同的 Kiosko 显示同一页。
- **显示时段。** 页面可以“始终”显示、仅在“工作时间”显示，或仅在“工作时间以外”显示（`when`，依据设置里的工作时间）。
- **固定。** 页面卡片上的图钉会让该页一直显示（`pinnedPage`；Home Assistant 和 API 也可以固定页面）。
- **插播动画**每隔一段时间盖在当前页面上播放，**警报**则凌驾一切，占据整块屏幕。

## 在以下情况显示此页面…

页面也可以在某件事发生时**自动出现**：游戏打开了、你在通话中、电价很贵、周五晚上、会议即将开始。打开该页面（点击其卡片，再点击画布上的空白处），在其设置的**在以下情况显示此页面…**中添加条件：

| 条件 | 满足的时候… |
|---|---|
| **某个程序打开时** | 有该名称的进程正在运行。通配符，不区分大小写：`steam*`、`obs*`、`zoom*`；多个用逗号分隔。 |
| **数据源的值** | 数据源在某个路径上的值符合比较，例如 `calls/active` · `active` · *为真*；`electricity/pvpc` · `now.price` · *大于* · `0.2`。 |
| **某个时段** | 本地时间落在该时段内，且在所选日期。`22:00` 到 `07:00` 跨越午夜。 |
| **本页某个组件紧急时** | 本页某个组件表示紧急（会议即将开始、有权限请求在等待）。 |

只要有一个条件满足，该页面就会取代轮播占据屏幕；都不满足后，轮播按挂钟时间恢复。带条件的页面**只在**条件满足时出现，除非你打开“也参与常规轮播”。

- **同时多个。** 每个条件都有**优先级**：最高者胜出。优先级相同的页面相互轮流。
- **不闪烁。** 情境页面出现后至少停留 20 秒，条件不再满足后再停留 10 秒，以防它再次满足（游戏重启、数值在阈值附近徘徊）。这两项按屏幕设置，在“防闪烁”中。优先级更高的页面无需等待。
- **先后顺序**：警报，然后是固定的页面，然后是情境页面，最后是轮播。情境页面显示期间，定时插播动画会等待。
- **这页为什么在屏幕上？** 编辑器在页面列表旁说明哪一页占据屏幕以及原因：*由此固定：游戏已打开 (steam)*。

条件可以有**名称**（“游戏已打开”）：编辑器会把它作为原因显示。在配置文件中，一个条件可以同时检查多项，须全部满足：

```json
"showWhen": [
  { "label": "游戏已打开", "priority": 5, "app": "steam*, *.x86_64" },
  { "label": "通话中", "priority": 9, "source": "calls/active", "path": "active" },
  { "time": { "start": "18:00", "end": "23:00", "days": [5, 6] }, "source": "electricity/pvpc", "path": "now.price", "op": "lt", "value": 0.1 }
]
```

比较方式（`op`）：`truthy`（没有 `value` 时的默认值）、`falsy`、`eq`（有 `value` 时的默认值）、`ne`、`gt`、`gte`、`lt`、`lte`、`contains`。尚未发送数据的数据源，或不存在的路径，永远不满足。即使没有组件显示该数据源，它也会运行。屏幕的防闪烁设置为 `"context": { "minMs": 20000, "holdMs": 10000 }`。

### 各系统上的程序

仅在有条件需要时，Kiosko 每 3 秒查看一次正在运行的程序，只用任何用户都能读取的信息：

- **Linux**：内核给每个进程的名称（截断为 15 个字符）以及启动时使用的名称（`argv[0]`，完整名称）。如果 `/proc` 以 `hidepid` 挂载，只能看到自己的进程。通过 Steam Proton 运行的游戏通常显示为其 `.exe`（`*.exe` 可全部匹配）。
- **macOS**：可执行文件的名称及其应用的名称（`zoom.us`、`OBS`）。
- **Windows**：映像名称，带或不带 `.exe`（`steam.exe`、`steam`）。

只读取名称，从不读取命令行。容器里或其他电脑上的程序看不到。

### 尚未支持

会议开始、Webhook、某块屏幕开始推流，目前还不是独立的条件；日历组件的紧急状态，或带有该值的数据源，可以覆盖其中一部分。
