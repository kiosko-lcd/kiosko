# 浏览器屏幕（平板、手机）

> **新功能，实验性。** 你网络中的任何浏览器都能全屏显示 Kiosko 的屏幕：墙上的旧平板、桌上闲置的手机。
> 无需购买硬件，也无需固件：打开一个地址，在编辑器中输入代码，就完成了。
> 使用 Kiosko 自有固件的 Wi-Fi 小屏幕，请参阅 [remote-screens.md](remote-screens.md)。

你将得到：

- **用代码配对。** 浏览器显示 6 位数字代码，你在编辑器中输入。只有你配对过的浏览器才能收到画面，而且传输经过加密。
- **跟随设备。** 屏幕采用浏览器窗口的尺寸，平板旋转时随之旋转。
- **自动恢复。** 平板休眠、Wi-Fi 中断或页面重新加载后，它会自动重连而无需重新配对，并立即显示当前画面。
- **编辑器保持私密。** 浏览器连接的是另一个只提供屏幕页面的小型服务器；编辑器仍只在这台电脑上监听。

## 开启网络屏幕

网络屏幕默认关闭，需要你手动开启。在编辑器的**屏幕**页面底部找到**网络屏幕（浏览器）**。开启后选择：

- **监听**：“本地网络”（所有网卡，通常选这个）、“仅限本机”（用于通过 USB 线连接的平板，参见[线缆模式](#线缆模式usb-连接的-android)），或本机的某个地址。
- **端口**：7429，除非已被占用。

随后卡片会显示要打开的地址（本机每个网络接口一个）及其二维码。

在配置文件中是这样的：

```json
"networkScreens": { "enabled": true, "host": "0.0.0.0", "port": 7429 }
```

防火墙必须允许平板访问该端口（在 Windows 上，询问时请允许 Node.js 访问专用网络）。

## 添加浏览器

1. 在平板或手机上打开编辑器显示的地址，例如 `http://192.168.1.20:7429/`（或扫描二维码）。页面会显示一个大大的 6 位数字代码，下方是浏览器的类型及其 ID 的 4 个字符。
2. 在编辑器中：**屏幕 → 添加屏幕 → 浏览器（平板、手机…）**。会列出等待配对的浏览器，以及它们的尺寸和地址。
3. 选择你的浏览器（如果只有一个在等待，则已自动选中），输入它的代码。错误的代码会被拒绝，浏览器会显示新代码，下一次尝试需要稍等片刻（每输错一次等得更久）。
4. 会出现一个新屏幕，尺寸与浏览器相同，并带有第一个页面。像编辑其他屏幕一样编辑它即可。

轻触页面进入全屏。在任意位置长按（或轻触右上角）打开菜单：全屏、取消配对。

如果要把浏览器配对到现有屏幕而不是新屏幕，请在该屏幕的卡片上使用**重新配对**。

没有浏览器显示某个屏幕时（标签页已关闭、平板休眠或离开网络），Kiosko 不再为它绘制任何内容，就像拔掉的面板一样；浏览器回来时会立刻收到一幅新画面。

## 尺寸与方向

开启**跟随浏览器的尺寸**（默认）时，屏幕采用浏览器窗口以设备像素计的尺寸（长边最多 1920），并在设备旋转时在横屏和竖屏之间切换，页面会像旋转任何副屏时一样重新排版。细微的变化（地址栏出现又消失）会被忽略。关闭它可以保留你自己设置的尺寸：浏览器会把画面尽可能放大显示。

## 保持屏幕常亮

除非页面要求，浏览器会让屏幕休眠。页面会尽力而为：

- **Wake Lock**，在浏览器允许的情况下：仅限安全页面（`https` 或 `http://127.0.0.1`，参见[线缆模式](#线缆模式usb-连接的-android)）。`http://192.168.x.x` 上的页面不属于安全页面。
- 其他情况下，播放一段**极小的静音视频**，持续播放可以让大多数手机浏览器保持唤醒。有些浏览器不认静音视频：这时请使用下面的方法之一。

页面的菜单会显示当前起作用的是哪一种。以下方法更可靠，与浏览器无关：

- 设备本身的设置：把屏幕超时设为最长；在 Android 上，“开发者选项 → 保持唤醒状态”可在充电时保持屏幕常亮。
- **Kiosk 浏览器应用**（Android 上如 Fully Kiosk Browser；iPad 上用“引导式访问”并把“自动锁定”设为“永不”）：全屏、保持常亮、开机自启。把它指向页面的地址即可。
- 把页面添加到主屏幕，打开时就不会显示浏览器的栏。

## 线缆模式（USB 连接的 Android）

通过 USB 线连接的 Android 平板完全不需要网络就能访问 Kiosko，而且是作为安全页面（因此 Wake Lock 可用）：

1. 在平板上启用“开发者选项 → USB 调试”；插上线并允许这台电脑。
2. 在编辑器中，把网络屏幕设为监听**仅限本机**（`"host": "127.0.0.1"`）：不会向网络暴露任何内容。
3. 在电脑上运行 `adb reverse tcp:7429 tcp:7429`。
4. 在平板上打开 `http://127.0.0.1:7429/`，按上文方法配对。

`adb reverse` 在拔掉线或平板重启之前一直有效：之后需要重新运行（可以用一个小脚本或 udev 规则自动完成）。

## 安全性

网络屏幕服务器向你网络中的任何人暴露的内容：

- 查看器页面（其 HTML、脚本、样式和图标）；
- 一个 WebSocket，浏览器通过它证明自己持有配对密钥，或显示代码等待配对。

其他请求一律返回 404。它是一个独立的服务器，而不是权限更少的编辑器服务器：它没有通往编辑器、编辑器 API、配置、日志或插件的路由，编辑器仍只在 127.0.0.1 上监听。

浏览器如何获得信任：

- **配对**使用 SPAKE2（与 ESP32 屏幕相同），基于浏览器显示的代码：必须有人从屏幕上读出代码并在编辑器中输入。错误的代码不会泄露任何信息，会让浏览器生成新代码，并让下一次尝试等待（5 秒，逐次翻倍，最多一分钟）。
- **会话**：每次连接时，双方都基于新的 nonce 证明自己持有密钥，之后每条消息都使用为该连接生成的密钥以 ChaCha20-Poly1305 加密封装。没有有效密钥的浏览器收不到任何画面；无法解开的消息会终止会话。
- **限制**：同时最多 32 个连接，每个地址 4 个 WebSocket，8 个等待中的浏览器，浏览器发来的每条消息最大 4 KB；其他网站的页面无法打开该 WebSocket。
- **撤销**：屏幕卡片上的“撤销”会从配置中删除密钥，并通知浏览器忘记它；浏览器会重新显示代码。页面菜单中的“取消配对”在平板上做同样的事。

它无法防范的情况：

- 页面通过普通 HTTP 提供：能够篡改你本地网络流量的人，可以向平板提供被修改的页面。使用线缆模式或你信任的网络可以避免这一点。
- 配对密钥保存在浏览器的存储中：拿到已解锁平板的人可以复制它。平板丢失时请撤销它。
- 你网络中的任何人都能打开该页面，设备也可能把自己加入等待中的浏览器列表；但配对仍然需要*你的*平板上显示的代码。输入之前请核对地址和那 4 个字符。

## 故障排除

- **页面打不开**：卡片上是否显示“已开启，端口 7429”？平板是否在同一网络中，防火墙是否放行？试试卡片上列出的其他地址。
- **列表中没有浏览器**：页面必须处于打开状态并显示代码。打开页面后休眠的平板会在半分钟后从列表中消失；唤醒它即可。
- **平板休眠时画面停止**：参见[保持屏幕常亮](#保持屏幕常亮)。平板唤醒后会自动恢复。
- **正常工作后又回到代码界面**：屏幕已被撤销或在 Kiosko 中被删除，或者浏览器的存储被清除了。重新配对即可。

消息定义在 [packages/core/src/browser/protocol.ts](../../packages/core/src/browser/protocol.ts) 中：即远程屏幕协议（[remote-screen.md](../remote-screen.md)）的消息，承载在 WebSocket 上，由浏览器发起连接并先发言。
