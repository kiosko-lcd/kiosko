# 通过 USB 连接副屏

**USB** 连接（`"device": { "driver": "usb" }`）让 Kiosko 通过 libusb 直接与利民 Thermalright LY 系列副屏（Trofeo Vision 9.16 及同系列；USB `0416:5408` 和 `0416:5409`）通信，不需要 Python，也不需要 `trcc serve`。

```json
"device": { "driver": "usb", "serial": "202592047DAE" }
```

- `serial`：USB 序列号。**有多块相同的副屏时，序列号是唯一能区分它们的依据**，所以请务必填写。找不到指定序列号的副屏时，Kiosko 会一直等它出现，绝不会换用另一块副屏（如果抢走另一个程序正在使用的同款副屏，会让那块副屏黑屏）。留空：使用找到的第一块副屏。
- `keepalive`：画面没有变化时，重新发送同一帧的间隔秒数（默认 1）。最后一帧发出 2–3 秒后，固件就会重新显示出厂 Logo。

`kiosko doctor` 会列出 libusb 能看到的副屏及其序列号；在编辑器的 **屏幕 → 添加屏幕 → 检测屏幕** 中也可以直接选择它们。

帧始终以 JPEG 格式发送。固件最多只接受约 511 871 字节，超过的帧会被**静默丢弃**；Kiosko 会读取副屏的确认应答，并在该屏幕的状态中提示你（“屏幕丢弃了一个 … KB 的帧：请降低 JPEG 质量”）。

## 拔掉的副屏会让它的屏幕暂停（在位检测）

副屏不在时，它的屏幕照样合成页面、绘制小组件、编码画面，白白耗费 CPU。所以 Kiosko 会**暂停副屏不在的屏幕**：不为它合成、绘制或编码任何东西，它的过场动画、动画和警报都会等待，只有它在显示的数据源和抓取也会停止。之后会以很低的开销重新查找（2 秒、4 秒、8 秒……最长每 30 秒一次；有 USB 热插拔事件时立即查找：Linux 上用 `/dev/bus/usb` 的 inotify，其他系统用 libusb 的热插拔事件），副屏一回来，屏幕就**用一帧全新的完整画面继续**。编辑器会显示“副屏未连接 · 已暂停（节省 CPU）”，`kiosko doctor` 会显示每个帧文件屏幕的在位情况。你关掉的屏幕仍然保持关闭：在位检测不是屏幕的开关。

- **USB** 连接：自动。没有插入带有该 `serial` 的 LY 副屏（没填序列号时：一块都没有）就算不在。只查看，不打开设备。
- **远程屏幕**：自动。离线（没有会话、没有 mDNS 广播）或未配对都算不在；它一广播就立即恢复。
- **帧文件**：Kiosko 看不到发送程序驱动的副屏，需要用 `presence` 告诉它怎么判断（不设置时屏幕和以前一样一直绘制）：

```json
"device": {
  "driver": "file",
  "dir": "$XDG_RUNTIME_DIR/kiosko/left",
  "presence": {
    "usb": { "vendorId": "0416", "productId": "5408", "serial": "202592047DAE" },
    "heartbeat": { "path": ".heartbeat", "maxAgeMs": 5000 }
  }
}
```

- `usb`：插入了具有这个厂商 ID、产品 ID（和序列号）的 USB 设备。只读：Linux 上从 sysfs 读取，完全不打开设备；其他系统上 libusb 会短暂打开设备读取序列号（每次插入只读一次），绝不占用它。发送程序继续使用副屏，不受打扰。
- `heartbeat`：发送程序驱动副屏期间会不断更新的文件；文件不存在或超过 `maxAgeMs`（默认 5000）就算不在。相对路径位于 `dir` 之内。`contrib/usb-sender` 里的发送程序在副屏连接期间，每秒更新一次它正在显示的文件夹里的 `.heartbeat`。
- `command`：`{ "argv": ["lsusb", "-d", "0416:5408"], "everyMs": 30000 }`：副屏在时以 0 退出的程序（不经过 shell）；每 `everyMs` 运行一次（最少 5 秒），超过 10 秒会被终止。导入配置时，它会和其他会运行程序的值一样列出来供你检查。

设置了多种检测时：**任何一种**说不在就算不在。无法判断的检测（没有 libusb、读不到序列号的同款副屏）会说“未知”，这样的屏幕照常绘制。

在编辑器中：**屏幕 → （该屏幕）→ 帧文件 → 副屏拔出时暂停**；**检测序列号** 会以只读方式列出该 VID:PID 的设备及其序列号，并标出哪个屏幕已经在用。

**相同的副屏必须填序列号。** 所有 Trofeo Vision 副屏都报告 `0416:5408`。没有 `serial` 时，Kiosko 只知道插着*某一块*副屏，永远不知道*是哪一块*，所以只有在**一块都没插**时才会暂停屏幕。三块拔掉两块、又没填序列号时，什么都不会暂停，这是有意为之：如果暂停了一块其实还在的副屏，它的画面就会冻住。`kiosko doctor` 会列出序列号（也可以用 `lsusb -v -d 0416:5408 | grep iSerial`）。

### 使用 trcc 发送程序（`contrib/usb-sender`）

每个发送程序按序列号驱动一块副屏，显示某个文件夹里的 `frame.jpg`。给每个帧文件屏幕设置*它自己的*发送程序的在位检测：

- 发送程序配置里没有 `wheel` 时，两种都可以：`usb` 加上该发送程序的 `serial`，不需要发送程序配合；`heartbeat` 还能发现发送程序没在运行。
- **有 `wheel`**（几块副屏每隔几个小时轮流显示各个文件夹）时，一块副屏显示的文件夹会变，它的序列号无法说明它在显示哪个屏幕：只用 **`heartbeat`**（`{ "path": ".heartbeat" }`）。发送程序更新的是它*此刻*显示的文件夹的心跳文件，所以只有正被某块已连接副屏显示的屏幕才会绘制；轮换时，新文件夹的心跳会在一秒内更新，它的屏幕随即恢复。

心跳需要更新后的 `kiosko-sender.py`（除非它的配置写了 `"heartbeat": false`，否则会更新 `.heartbeat`）。旧版发送程序从不更新它，屏幕就会一直暂停：请先更新发送程序。

## 各系统需要做什么

**Linux。** 你的用户必须有权限打开这个设备。如果 `kiosko doctor` 显示 `(unreadable)` 或访问错误，请添加一条 udev 规则，然后重新插拔副屏：

```
# /etc/udev/rules.d/99-kiosko-lcd.rules
SUBSYSTEM=="usb", ENV{DEVTYPE}=="usb_device", ATTR{idVendor}=="0416", ATTR{idProduct}=="540[89]", TAG+="uaccess"
```

（然后运行 `sudo udevadm control --reload && sudo udevadm trigger`。）Kiosko 使用副屏期间会暂时分离内核驱动，停止时再交还。两个程序不能同时使用同一块副屏：要交给 Kiosko 的副屏，请先停止正在驱动它的 `trcc serve` 或 `kiosko-sender`。

**Windows。** libusb 只能看到使用 **WinUSB** 驱动的设备，所以每块副屏都要先用免费工具 [Zadig](https://zadig.akeo.ie/) 换上 WinUSB 驱动。每块副屏只需要做一次：

1. 下载并运行 Zadig。它需要管理员权限，弹出“用户账户控制”窗口时请点击 **是**。
2. 在菜单中勾选 **Options → List All Devices**（列出所有设备），否则列表里可能看不到副屏。
3. 在下拉列表中选择副屏。辨认方法是看下方显示的 USB ID：`0416` 和 `5408`（或 `5409`）。**注意不要选错**，选成鼠标、键盘或其他设备会导致它们无法正常工作。
4. 在箭头右侧的驱动框中选择 **WinUSB**。
5. 点击 **Replace Driver**（替换驱动），等待完成。

换上 WinUSB 之后，利民官方的 TRCC 软件就识别不到这块副屏了；如果需要换回来，可以在“设备管理器”中恢复原来的驱动。没有安装 WinUSB 时，`kiosko doctor` 会显示 `LIBUSB_ERROR_NOT_SUPPORTED`。

**macOS。** 无需安装任何东西。

原生模块（`usb`）是**可选**依赖，提供 Linux、macOS 和 Windows 的预编译二进制文件；即使它无法加载，Kiosko 的其他功能仍然正常，这种连接方式也会告诉你原因。

## 开发状态

本功能依据 [thermalright-trcc-linux](https://github.com/Lexonight1/thermalright-trcc-linux) 9.12 实现的协议编写：对于 `packages/usb-ly` 中的 22 个测试帧（由 `trcc` 本身生成），每一帧发出的字节流与 `trcc` 完全相同，其余部分则用模拟固件进行测试。**目前还没有在真实的副屏上运行过**，也还没有在 macOS 或 Windows 上运行过：请把它当作实验性功能，并保留 `trcc serve` 或帧文件发送程序作为备用方案。
